# CRM Sales Pipeline Analysis

## Business Question
Where in the sales funnel are deals being lost, and which segments, lead sources, and reps convert best?

## Dataset
- **Source:** Synthetic, generated by `generate_data.py` to mirror a typical Salesforce opportunity export. **Stated upfront, not buried:** real CRM exports aren't public, so this is built to demonstrate the analysis technique, not to claim real findings about any company. Realistic signal is baked in on purpose (segment and lead source affect win probability, rep skill varies) so the SQL queries have real structure to find.
- **Size:** 650 opportunities, `data/opportunities.csv`.
- **Description:** One row per opportunity: segment, lead source, owner, deal amount, created/close dates, cycle length, funnel stage reached, outcome (Won/Lost/Open), and loss reason. Full column definitions in [`data/DATA_DICTIONARY.md`](data/DATA_DICTIONARY.md), including how each column maps to a real Salesforce `Opportunity` export.

## Tools Used
- Python (numpy, pandas): synthetic data generation, input validation
- SQL (SQLite): 7 named analysis queries (`queries.sql`)
- matplotlib: funnel chart (with stage-to-stage conversion %), win-rate-by-segment chart

## Key Findings
1. **Negotiation is the single biggest funnel drop-off**, at 28.7% of deals that reach it not surviving it, more than any other stage. (Of deals that do reach Negotiation, 62.9% ultimately close-won.)
2. **Segment drives win rate more than any other factor tested:** SMB converts at 40.5% vs. Enterprise at 31.0%.
3. **Lead source matters just as much:** Inbound converts at 41.9% vs. Outbound at 25.0%, nearly a 17pt gap.
4. **Enterprise's #1 loss reason is structurally different from SMB's:** No Budget (38.3% of Enterprise losses) vs. Price (41.7% of SMB losses). *Caveat: Enterprise loss reasons are based on 60 lost deals total (Enterprise is ~15% of the dataset by design): directional, not a precise split, until the sample is larger.*

## Recommendations
- Fix the Negotiation stage first: it's the largest single-stage drop-off in the pre-close funnel, and closing that gap compounds through every stage after it.
- Shift outbound spend toward Inbound-shaped motions where the win-rate data supports it, rather than splitting effort evenly across sources.
- Build a segment-specific loss-reason playbook for Enterprise (No Budget-driven) instead of reusing the SMB objection-handling script, keeping the small-sample caveat in mind before over-indexing on the exact split.

## On the Tableau gap
This role's posting lists Tableau as a plus, and the honest state of this repo is: no Tableau workbook. Building one needs a Tableau Public account and its desktop/web authoring tool, both outside what this environment can do (parallel to why there's no Power BI file in the `elastic-revenue-forecast` repo). What's here instead: `output/*.csv` per query, already shaped for a direct `Get Data > Text/CSV` import into Tableau Public with no transformation needed, so building the workbook on top of this is a matter of connecting Tableau to those files, not re-deriving the analysis.

## Files
- `generate_data.py`: builds `data/opportunities.csv` (synthetic, generation logic documented in the file)
- `data/DATA_DICTIONARY.md`: column definitions and the Salesforce field mapping
- `queries.sql`: 7 named queries: win rate by segment/source, cycle length, funnel by stage, rep performance, loss reasons by segment, open pipeline
- `analyze.py`: validates the input, runs every query, writes one CSV per query plus 2 charts to `output/`
- `output/exec_summary.md`: full write-up with all computed numbers, regenerated on every run

## Methodology
`generate_data.py` samples segment, lead source, and rep per opportunity, then derives a win probability from those factors (segment base rate x source multiplier x rep skill) before sampling the actual outcome, so the findings above are the data-generating process being correctly recovered by the SQL. That recovery is the point: the technique (funnel construction via furthest-stage-reached, cohort win rates, loss-reason decomposition) carries over unchanged to a real Salesforce export. `analyze.py` validates the input first (no nulls in key columns, positive amounts, unique IDs, valid outcome values, cycle_days present on every closed deal) before any query runs.

**Limitations, stated plainly:** every number above is real *output of this script* run against *synthetic* data; it is not evidence about any actual company's pipeline. On a real export, none of these relationships are known ahead of time the way they are here by construction, and the Enterprise segment's small sample size (noted above) means its specific percentages should be read as directional.

